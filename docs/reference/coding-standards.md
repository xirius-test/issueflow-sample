# Coding standards

This file is a **starter stub**. It ships empty on purpose — this workflow
does not know your stack, your linter, or your team's conventions.

Producing-stage workflow guidance and quality-gate agent charters reference
this file **conditionally**: *"if `docs/reference/coding-standards.md` exists
and has content, follow it; otherwise, apply general best practice for this
repository's language and stack."* Filling this in raises the bar every agent
is held to — for this repository specifically — with zero charter changes
required.

## Fill this in with your team's own rules, for example:

- Language/framework conventions (formatting, naming, idioms)
- Required tooling and how to run it (linter, type-checker, formatter) and
  what "clean" means (must the build be green before merge?)
- Test expectations (what must be covered, how to run the suite)
- File/module size or complexity limits
- Anything your team currently enforces only in code review

Until you fill this in, agents fall back to general best practice for
whatever language/framework they find in this repository — never a hardcoded
assumption about your stack.
